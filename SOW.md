## PlatePulse: ТЗ v1

### Цель и принципы

Первый релиз закрывает питание семьи из двух человек: меню на неделю,
заготовки, список покупок и учёт калорий. Часы, весы и тренировки — во втором
релизе.

• Дневник = план + отклонения. По умолчанию съедено то, что стоит в меню.
Вручную вводятся только замены и перекусы.
• Готовим партиями. Блюдо готовится одной заготовкой и раскладывается
на несколько приёмов пищи.
• Минимум ручного ввода. КБЖУ продуктов берётся из открытых баз, неделя
собирается из шаблонов привычных блюд.
• Двое, у каждого свои цели. В будни у каждого своя еда; завтраки и
выходные общие: одно блюдо, разные порции.
• Семья как пространство. Все данные принадлежат семье, а не пользователю,
чтобы позже открыть сервис другим без переписывания.

### Сценарии использования

Неделя проходит один цикл: спланировали → закупились → приготовили заготовки
→ едим и отмечаем отклонения.

1. Планирование недели. Берём шаблон или копируем прошлую неделю и правим.
Будни: у каждого своя сетка. Завтраки и выходные: общие приёмы пищи, одно
блюдо с порцией для каждого.
2. Предложение заготовок. Система видит, какие блюда повторяются за неделю,
и предлагает приготовить их одной партией. Если срок хранения не дотягивает
до последнего дня, она делит блюдо на две партии или предлагает заморозку.
3. Список покупок. Собирается из заготовок и свежих блюд, сгруппирован по
отделам магазина, округлён до упаковок. В магазине отмечаем купленное галочками.
4. День заготовок. Отмечаем партию «приготовлено», и она появляется в
холодильнике со сроком годности.
5. Каждый день. Один тап «съел по плану», либо замена или перекус. Итог дня
видно рядом с целью каждого.
6. Конец недели. Сводка калорий по каждому и остатки заготовок, которые
переходят на следующую неделю.

### Доменная модель

Центральная сущность — заготовка (партия): она связывает рецепт с меню и с
закупкой. Всё ниже принадлежит семье.

| Сущность | Что хранит | Ключевые поля |
| ----- | ----- | ----- |
| Household (семья) | Рабочее пространство, владелец всех данных | name |
| Member (участник) | Пользователь внутри семьи | user, household, role |
| Goal (цель) | Норма КБЖУ участника, меняется со временем | member, kcal, protein, fat, carbs, valid_from |
| Product (продукт) | КБЖУ на 100 г и как он продаётся | name, kcal/protein/fat/carbs per 100 g, category (отдел магазина), pack_grams, barcode, source |
| Recipe (рецепт) | Блюдо и правила его хранения | name, tags (завтрак, обед…), cooked_weight_g, fridge_days, freezable |
| RecipeIngredient | Состав рецепта в сыром весе | recipe, product, grams |
| MealSlot (приём пищи) | Ячейка меню | household, date, meal_type, is_shared |
| PlanEntry (порция в плане) | Что ест конкретный человек в этой ячейке | slot, member, recipe, batch (nullable), portion_g |
| PrepBatch (заготовка) | Партия блюда, приготовленная заранее | recipe, cook_date, total_weight_g, status (planned / cooked / finished), expires_at |
| DiaryEntry (отклонение) | Замена или перекус вместо плана | member, date, meal_type, plan_entry (nullable), kind (replace / extra / skip), product или recipe, grams |
| ShoppingList / ShoppingItem | Закупка на период | week_start; product, need_g, packs, checked |
| WeekTemplate | Привычная неделя для быстрого старта | household, name, слоты с рецептами и порциями |
| PantryItem (опционально) | Что есть дома, грубо | product, approx_g |

Порции в плане и в дневнике хранятся в граммах готового блюда. Поэтому у
рецепта есть cooked_weight_g: макароны набирают вес при варке, мясо теряет.

### Ключевая бизнес-логика

Три расчёта несут весь продукт; каждый живёт в сервисном слое и покрыт тестами.

1. КБЖУ порции. Нутриенты рецепта считаются по сырому составу, а порция — как
доля готового веса:

K_{portion} = \frac{portion\_g}{cooked\_weight\_g} \cdot \sum_i \frac{grams_i
\cdot kcal_i}{100}

Так же считаются белки, жиры и углеводы. Все значения в Decimal, округление
только при выводе.

1. План заготовок.

- Порции недели группируются по рецепту.
- Каждая порция должна попасть в окно cook_date ≤ дата ≤ cook_date + fridge_days.
- Не влезает в одно окно → две партии или заморозка, если freezable.
- Вес партии = сумма порций, сырые ингредиенты = состав × (вес партии / cooked_weight_g).
- Порция, у которой есть batch, при списании уменьшает остаток партии; партия
закрывается, когда остаток равен нулю или истёк срок.

1. Список покупок.

- Ингредиенты всех партий недели плюс свежих блюд без партии.
- Минус PantryItem, если кладовая ведётся.
- Группировка по category, округление вверх до упаковки: packs = ceil(need_g / pack_grams).

1. Итог дня. Для участника и даты: порции плана, не перекрытые отклонениями,
плюс записи DiaryEntry типа replace и extra. Отклонение skip убирает порцию из
итога. Сравнение с Goal, действующей на эту дату.

### API на django-ninja

Один Router на модуль, префикс /api/v1, JWT в заголовке; семья берётся из
токена, а не из URL.

| Модуль | Метод и путь | Что делает |
| ----- | ----- | ----- |
| auth | POST /auth/register, /auth/token, /auth/refresh | Регистрация и токены |
| household | GET /household, POST /household/invites | Семья, приглашение второго участника |
| goals | GET/PUT /members/{id}/goal | Норма КБЖУ участника |
| products | GET /products?q=&barcode= | Поиск по своей базе и по внешней |
| products | POST /products, PATCH /products/{id} | Свой продукт или правка |
| recipes | CRUD /recipes | Рецепт с составом и сроком хранения |
| recipes | GET /recipes/{id}/nutrition?portion_g= | КБЖУ на порцию |
| plan | GET /weeks/{week_start} | Вся неделя: слоты, порции, итоги дней |
| plan | PUT /weeks/{week_start}/entries | Массовое сохранение сетки недели |
| plan | POST /weeks/{week_start}/copy-from/{other_week} | Копия прошлой недели |
| plan | POST /weeks/{week_start}/apply-template/{id} | Применить шаблон |
| prep | POST /weeks/{week_start}/prep/suggest | Предложение заготовок по плану |
| prep | POST /prep-batches, POST /prep-batches/{id}/cooked | Создать партию, отметить приготовленной |
| shopping | POST /weeks/{week_start}/shopping-list | Сгенерировать список покупок |
| shopping | PATCH /shopping-items/{id} | Отметить купленное |
| diary | POST /diary/{date}/confirm | «Съел по плану» за день или приём пищи |
| diary | POST /diary, DELETE /diary/{id} | Замена, перекус, пропуск |
| stats | GET /stats/daily?member=&from=&to= | КБЖУ по дням против цели |

### Этапы разработки

Пользоваться можно уже после третьего этапа: меню на неделю полезно и без заготовок.

1. Каркас. Docker Compose (Postgres, Redis), django-ninja, JWT, семья,
участники, цели. Ruff, mypy, pytest, CI.
2. Продукты и рецепты. КБЖУ, импорт продукта по штрихкоду или названию из открытой базы (например, Open Food Facts), расчёт КБЖУ порции.
3. Меню на неделю. Слоты, общие приёмы пищи, копирование недели, шаблоны.
4. Заготовки. Партии, сроки хранения, предложение заготовок, списание порций.
5. Список покупок. Генерация, группировка по отделам, упаковки, галочки.
6. Дневник и статистика. «Съел по плану», отклонения, итоги дня и недели.
7. Интерфейс. Мобильная веб-версия поверх API.

Следующий релиз: данные с часов и весов (Apple через Health Auto Export,
Huawei через Health Kit), тренировки, AI-подбор меню и разбор рецептов из текста.

Открытые вопросы

- [ ] Кто планирует неделю: один человек или оба, каждый свою часть?
- [ ] Сколько дней заготовок в неделю: один или два?
- [ ] Обеды в будни берёте с собой в контейнерах? Тогда заготовку нужно сразу
делить на порции.
- [ ] Вести «что есть дома» или только список покупок? Как сейчас жена следит
за продуктами?
- [ ] Интерфейс: HTMX (уже есть опыт) или SPA?
- [ ] Проверить, сколько из 20 реальных продуктов из вашего магазина находится
в открытой базе.
